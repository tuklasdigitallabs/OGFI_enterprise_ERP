## Governance boundary

## Scope

Batch F implements RS1-S059 through RS1-S070: primary Accounting Book, minimum Chart of Accounts, Accounting Period, Goods Receipt Posting Rule, source-posting eligibility, balanced Journal generation, source traceability, source-posting idempotency, explicit missing-rule and closed-period failure, consumer recovery and visible Finance posting status.

## Approved architecture

- Introduce `Ogfi.Modules.Finance` and the Finance-owned PostgreSQL `finance` schema.
- Finance owns Accounting Books, Accounts, Accounting Periods, Posting Rule Versions, Finance Source Postings, Journals and Journal Lines.
- Legal Entity is the accounting boundary; RI-01 supports one primary Book per Legal Entity.
- The reference entry is Debit Inventory Asset / Credit GRNI for each immutable Goods Receipt line net amount.
- `GoodsReceiptPostedV1` provides operational facts only. Finance never queries Procurement private tables and Procurement never selects GL accounts.
- Source currency must equal Book functional currency for RI-01.
- Business Date must resolve to exactly one OPEN Accounting Period.
- Posting Rules are immutable, versioned, effective-dated and Finance-owned.
- Finance Source Posting is the durable `PENDING` / `POSTED` / `FAILED` operational-to-accounting boundary and retains an immutable source snapshot.
- Source posting is unique by tenant, source type and source event ID; one source event creates at most one Journal.
- Source effect, validation, Journal, Journal Lines and POSTED status commit atomically in Finance.
- Every posted Journal balances exactly and posted accounting history is immutable.
- Procurement outbox fan-out uses durable per-consumer delivery state for `inventory.stock-consequence` and `finance.financial-consequence`.
- Business/configuration failures create explicit FAILED Source Posting state with no guessed fallback Journal.
- Replay uses the Finance-owned source snapshot and original source identity.
- Transient retry and crash-after-commit redelivery cannot duplicate Finance effects.
- All Finance tenant tables use enabled and forced PostgreSQL RLS and tenant-aware worker execution.
- Batch F frontend scope is Finance Journal View and Finance Posting/Error Status View using generated typed APIs.
- AP, payments, tax, FX, manual Journals, reversals, period close/reopen and full valuation/reporting are excluded.
